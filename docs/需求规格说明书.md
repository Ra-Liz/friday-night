## 1. 引言

### 1.1 目的
本文档细化「FridayNight 解冻倒计时网页」的产品需求，作为后续设计、开发、测试与验收的依据。

### 1.2 背景
「Friday Night 解冻」是近期抖音流行梗：主人公被冰封，一到周五夜晚（19:00）即「解冻」开唱 FridayNight，周末结束后再次被冻住，循环往复。本项目将该梗产品化为一个可分享、可反复访问的倒计时网页。

### 1.3 术语定义

| 术语 | 定义 |
| --- | --- |
| 解冻进度（Unfreeze Progress） | 0%–100% 的数值，表示主人公从完全冰封到完全解冻的程度 |
| 上冻进度（Freeze Progress） | 0%–100% 的数值，表示周末期间视频画面被冰封的程度 |
| 状态机 | 页面依据当前时间所处区间的展示模式（解冻倒计时 / 视频播放 / 逐步上冻） |
| 锚点时间 | 状态机的边界时刻：周一 00:00、周五 19:00、周六 00:00 |

### 1.4 约定
- 一周以 **周一 00:00:00 为起点**（ISO 8601 / 中国习惯）。
- 所有时间均取 **用户设备本地时间**，不做时区转换。
- 「周五 19:00」指用户本地时间的本周五 19:00:00。

## 2. 产品概述

### 2.1 产品目标
做一个轻量、可病毒传播的娱乐网页：用户任意时刻打开，都能看到主人公当前处于「冰封—解冻—开唱—再上冻」循环的哪个阶段，并距下一个关键节点还有多久。

### 2.2 目标用户与场景
- 主要通过微信/飞书/抖音等社交分享链接进入的普通用户。
- 场景一（工作日）：打开网页看到主人公被冰封，倒计时「距 FridayNight 解冻还有 X 天 X 时 X 分 X 秒」，冰封程度随接近周五逐渐减轻。
- 场景二（周五 19:00 后）：进入即看到视频循环播放。
- 场景三（周末）：视频仍循环播放，但画面逐渐被冰封覆盖。

### 2.3 产品形态
- 纯静态单页（HTML + CSS + JS），可部署至任意静态托管。
- 无登录、无后端、无数据上报。

## 3. 功能需求

### 3.1 FR-01 周状态机与进度计算

页面在任意时刻必须依据**当前本地时间**确定所处状态：

| 状态 | 时间区间（本地时间） | 持续时长 | 展示内容 |
| --- | --- | --- | --- |
| S1 解冻倒计时 | 周一 00:00:00.000 ≤ t < 周五 19:00:00.000 | 115 小时 | 主人公图片 + 解冻特效 + 倒计时 |
| S2 解冻开唱 | 周五 19:00:00.000 ≤ t < 周六 00:00:00.000 | 5 小时 | 视频无特效循环播放 |
| S3 逐步上冻 | 周六 00:00:00.000 ≤ t < 下周一 00:00:00.000 | 48 小时 | 视频循环播放 + 逐步增强的冻结特效 |

进度公式：

- 解冻进度 `P_unfreeze = (t − 周一00:00) / (周五19:00 − 周一00:00)`，即 `/ 115h`，取 0%–100%。
- 上冻进度 `P_freeze = (t − 周六00:00) / (周一00:00 − 周六00:00)`，即 `/ 48h`，取 0%–100%。

要求：
1. FR-01-1 打开页面时立即按上表计算状态，无中间 loading 状态暴露给用户（资源加载用骨架/占位背景兜底）。
2. FR-01-2 页面停留在前台时，跨越任一锚点时间必须**自动切换状态**，无需刷新（每秒 tick 检测 + 锚点定时器双保险）。
3. FR-01-3 浏览器休眠/后台标签页恢复（`visibilitychange`、`focus` 事件）后立即重算状态与进度，允许跳帧但不允许停留在旧状态。

### 3.2 FR-02 倒计时展示（S1 状态）

1. FR-02-1 页面显示距「周五 19:00 解冻」的剩余时间，格式 `X天 XX:XX:XX`（天/时/分/秒），每秒刷新。
2. FR-02-2 同屏展示当前解冻进度百分比（整数），如 `解冻进度 37%`。
3. FR-02-3 倒计时数字变化有轻微动效（如秒位跳动），不遮挡主人公展示。

### 3.3 FR-03 解冻特效分级展示（S1 状态）

页面中央展示主人公图片，冰封视觉随 `P_unfreeze` 分级变化。特效分五档，档间过渡平滑（≤1.5s 渐变）：

| 档位 | 进度区间 | 视觉效果（验收锚点） |
| --- | --- | --- |
| L0 完全冰封 | 0%–15% | 主人公被不透明冰块完整包裹，整体偏蓝白色调，表面有霜花/冰纹覆盖 |
| L1 冰面开裂 | 15%–40% | 冰面出现明显裂纹并向外扩散，冰块边缘开始有融水滴落效果 |
| L2 半解冻 | 40%–70% | 冰块上半部分破碎脱落，主人公头部/上半身清晰露出，残冰悬挂 |
| L3 接近解冻 | 70%–95% | 仅脚部/局部残留小块冰，人物基本清晰，色调恢复正常 |
| L4 蓄力待发 | 95%–100% | 人物完全清晰，轻微发光/抖动「蓄力」动效，暗示即将解冻 |

要求：
1. FR-03-1 档位切换必须平滑过渡，禁止生硬跳变。
2. FR-03-2 同一档位内部进度也需有连续变化（如裂纹数量、融水速率随进度递增），而非五张静态图硬切。
3. FR-03-3 图片为主视觉，居中占屏幕显著区域（详见 §5 布局）。

### 3.4 FR-04 解冻成功转场（S1 → S2）

1. FR-04-1 到达周五 19:00:00 瞬间（或用户在 S1 期间页面跨过该时刻），播放「冰块爆裂」转场动画（≤2s），随后进入视频播放。
2. FR-04-2 若用户恰在周五 19:00 之后首次打开页面，直接进入 S2，可省略爆裂动画（允许带一个轻量入场动效）。
3. FR-04-3 转场期间倒计时区域替换为「解冻成功 🎉」类文案，停留 ≥1s 后由视频接管。

### 3.5 FR-05 视频循环播放（S2/S3 状态）

1. FR-05-1 到达 S2 后自动循环播放 FridayNight 演唱视频，循环间隙无黑屏闪烁（原生控制条隐藏）。
   - FR-05-1a（v1.1 变更）页面刷新后恢复上次播放位置：仅恢复本播放周期（本周五 19:00 起）内的记录；跨周期或距结尾 <2s 时从头播放。
   - FR-05-1b（v1.1 变更）S2/S3 提供底部进度条，支持点击与拖拽选择播放进度，进度实时可视化。
2. FR-05-2 移动端自动播放须满足 `muted` + `playsinline`（iOS WKWebView / 微信浏览器约束）；首次自动播放被浏览器拦截时，展示「点击开始」兜底交互，点击后播放并尽量恢复声音（提供静音/取消静音按钮）。
3. FR-05-3 视频默认等比裁剪铺满中央展示区（cover），不允许拉伸变形；窄视口（视口宽高比 < 16:10，如手机竖屏）切换为等比完整展示（contain，黑边居中），保证视频画面完整（v1.2 变更）。
4. FR-05-4 弱网/视频加载失败时展示静态兜底图 + 重试按钮，不阻塞状态机运行。

### 3.6 FR-06 周末逐步上冻特效（S3 状态）

视频持续循环，画面冻结程度随 `P_freeze` 增强，分三档：

| 档位 | 上冻进度 | 视觉效果（验收锚点） |
| --- | --- | --- |
| F0 结霜 | 0%–30% | 画面四角/边缘出现冰晶与白霜，中心仍清晰 |
| F1 冰封蔓延 | 30%–70% | 冰层由边缘向中心蔓延，画面明显偏蓝、边缘出现冰挂，视频清晰度下降 |
| F2 完全上冻 | 70%–100% | 画面几乎被冰覆盖，仅隐约可见视频轮廓，冻结纹理完整 |

要求：
1. FR-06-1 档内进度连续变化（冰晶覆盖面积随进度递增），档间平滑过渡。
2. FR-06-2 上冻特效叠加于视频之上，视频本身继续播放（不降帧、不暂停）。
3. FR-06-3 上冻同时展示一行轻量文案（如「周末结束倒计时」+ 剩余时间），不遮挡主视觉。

### 3.7 FR-07 周一重置

1. FR-07-1 跨过周一 00:00:00 的瞬间，状态切回 S1，解冻进度归 0%，主人公回到 L0 完全冰封，倒计时重新开始。
2. FR-07-2 S3 → S1 的切换可带「彻底冻住」的短转场（≤1.5s），随后进入 L0。
3. FR-07-3 重置无需刷新页面；用户在周一之后打开页面同样直接进入 S1 / L0。

        周一 00:00                周五 19:00            周六 00:00            下周一 00:00
────────────┬───────────────────────────┬────────────────────────┬────────────────────────┬─────▶

   特效 L0 → L4    │                           │      特效 F0 → F2        │

## 5. 界面与响应式要求

### 5.1 布局（三状态共用骨架）
- 顶部：标题区（「FridayNight 解冻倒计时」及状态副标题）。
- 中央：主视觉区（主人公图片或视频），为此前页面最大视觉区域。
- 主视觉下方/叠加角落：倒计时或状态文案区。
- 允许深色主题为默认基调（契合冰封/夜晚氛围）。

### 5.2 响应式（FR-08）
1. FR-08-1 断点：`< 768px` 视为移动端布局，`≥ 768px` 为 PC 布局；另对竖屏/横屏分别适配。
2. FR-08-2 主视觉在主流视口（375×667 至 1920×1080）内完整可见、不裁切关键人物主体、不出现横向滚动条。
3. FR-08-3 移动端字号、按钮点击区域 ≥ 44×44px；视频区域点击不误触发页面滚动。

### 5.3 性能（FR-09）
1. FR-09-1 目标 60fps：解冻/上冻动效优先使用 CSS `transform`/`opacity` 与 GPU 合成，避免大面积 JS 逐帧重绘。
2. FR-09-2 首屏可交互目标 ≤ 2s（本地静态资源）；视频采用首帧占位图（poster）。
3. FR-09-3 素材（图片/视频/特效纹理）需做体积控制，视频建议提供压缩版本。

### 5.4 兼容性（FR-10）
1. FR-10-1 支持最近两个大版本的 Chrome、Safari、Edge，以及 iOS Safari、微信内置浏览器、抖音内置浏览器（WebView 场景为主传播渠道，必须重点验证）。
2. FR-10-2 不支持的环境（如极老浏览器）降级为静态图 + 纯文字倒计时，不白屏。

## 6. 素材需求

| 素材 | 规格要求 | 来源 |
| --- | --- | --- |
| 主人公图片 | 高清单人立绘/照片，透明背景 PNG 优先；或分档位多帧图 | 需用户提供或先用占位图 |
| FridayNight 演唱视频 | MP4 (H.264)，≤ 20MB，建议 720p+ | 需用户提供（注意版权），开发期用占位视频 |
| 冰纹/裂纹/霜花纹理 | 可平铺或叠加的 PNG/WebP | 可程序化生成或 CC0 素材 |
| 「点击开始」/「重试」图标 | SVG | 程序内置 |

> 注：若涉及真实歌曲 MV/演唱视频，上线前需确认版权或替换为无版权素材。

## 7. 边界与异常场景

| # | 场景 | 期望行为 |
| --- | --- | --- |
| E-1 | 用户在周五 18:59 打开，页面跨过 19:00 | 前台时自动触发爆裂转场进入 S2，无需刷新 |
| E-2 | 用户在周日 23:59 打开 | 直接进入 S3/F2，画面几乎全冰 + 周末结束倒计时 |
| E-3 | 移动端锁屏数小时后恢复 | `visibilitychange` 触发重算，立即同步到正确状态 |
| E-4 | 用户手动修改系统时间 | 以设备时间为准（无后端校时，属已知限制），页面按修改后时间渲染 |
| E-5 | 弱网下视频加载失败 | S2/S3 显示静态兜底图 + 重试按钮，倒计时与状态机不受影响 |
| E-6 | 浏览器禁止自动播放 | 「点击开始」兜底，点击后播放（默认静音，提供取消静音按钮） |
| E-7 | 页面在后台标签页长时间挂起 | 节流不视为故障；回到前台必须立即校正状态 |

## 9. 非目标（本期不做）

- 多语言、多时区配置（一律设备本地时间）。
- 分享卡片自定义（OG 标签仅给默认值）。
- 音量记忆、播放历史、访问统计等个性化能力。
- 后端校时与推送。
