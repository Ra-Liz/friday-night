## 1. 总体技术选型

| 决策点 | 选型 | 理由 | 备选与否决原因 |
| --- | --- | --- | --- |
| 运行时框架 | **原生 HTML/CSS/JS（ES Module），无框架** | 单页、3 个状态、无用户输入状态管理；React/Vue 引入 ~40KB+ 运行时纯属浪费 | Vue/React：为组件化牺牲体积与加载速度，收益为零 |
| 构建工具 | **Vite** | 开发热更新 + 一条命令出 `dist/` 静态产物；对无依赖项目零负担 | 纯手写零构建：可行，但压缩/版本号/占位素材管理繁琐，收益低 |
| 部署形态 | 静态托管（任意对象存储/静态服务器/妙搭） | 无后端、无接口 | — |
| 特效实现 | **CSS 分层 + CSS 自定义属性驱动**（详见 §4） | 性能、体积、微信/抖音 WebView 兼容性三优 | Canvas/WebGL：见 §4.1 对比 |
| 时钟来源 | `Date`（设备本地时间）+ `Intl`/`getDay` 计算锚点 | SRS Q-2 默认方案：纯前端无服务端校时 | NTP/API 校时：非目标 |

**性能预算**：首屏 JS ≤ 10KB（gzip）、CSS ≤ 15KB（gzip）、除视频外素材 ≤ 500KB；视频单独 ≤ 20MB（SRS §6）。

## 2. 模块架构

```
┌────────────────────────────────────────────────────────┐
│                      index.html                        │
│  ┌───────────────┐  ┌──────────────┐  ┌─────────────┐  │
│  │   clock.js    │─▶│ controller.js│─▶│  effects.js │  │
│  │ 时间源/tick/   │  │ 状态切换/     │  │ 写 CSS 变量/ │  │
│  │ 锚点定时器     │  │ 转场编排      │  │ 档位类名     │  │
│  └───────┬───────┘  └──────┬───────┘  └──────┬──────┘  │
│          │                 │                 │         │
│          ▼                 ▼                 ▼         │
│  ┌──────────────────┐  ┌─────────────────────────────┐ │
│  │ stateMachine.js  │  │        media.js             │ │
│  │ 纯函数：computeState│  │ 视频播放/自动播放兜底/重试   │ │
│  └──────────────────┘  └─────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

| 模块 | 职责 | 关键导出（契约） |
| --- | --- | --- |
| `clock.js` | 时间源抽象；整秒对齐 tick；锚点 setTimeout；visibilitychange/focus 触发即时重算 | `startLoop({onTick})`, `stopLoop()` |
| `stateMachine.js` | **纯函数**，无副作用，唯一状态权威 | `computeState(now: Date) → { state: 'S1'\|'S2'\|'S3', progress: number(0–1), stage: 'L0'…'L4'\|'F0'…'F2', anchors: {next: number, label: string} }` |
| `controller.js` | 订阅 tick；diff 状态变化；编排转场（S1→S2 爆裂、S3→S1 冻结）与文案/倒计时渲染 | `init()` |
| `effects.js` | 把 `progress`/`stage` 写成 CSS 自定义属性与 `data-stage` 类名；档位切换平滑过渡由 CSS transition 兜底 | `apply(stateResult)` |
| `media.js` | video 元素生命周期：进入 S2/S3 时激活、离开时暂停卸载；自动播放 promise 兜底；错误重试与静态兜底 | `activateVideo()`, `deactivateVideo()`, `onClickToStart()` |

**数据流**：`clock tick(每秒) → computeState(now) → controller diff → effects.apply（写 CSS 变量）/ media 切换 / 文案渲染`。JS 每秒仅做一次轻量计算与 DOM 属性写入，全部连续动效由 CSS 常驻动画承担（满足 FR-09-1）。

## 3. 状态机实现方案

### 3.1 锚点计算（唯一算法，所有时间判断都走它）

以「now 所在周的周一 00:00」为基准锚（周日归入该周，即周一为一周第一天）：

```js
// stateMachine.js 核心逻辑（示意）
function computeState(now) {
  const d = new Date(now);
  d.setHours(0, 0, 0, 0);
  const daysSinceMonday = (d.getDay() + 6) % 7;   // 周一=0 … 周日=6
  const monday00  = d.getTime() - daysSinceMonday * 86400_000;
  const fri19     = monday00 + 115 * 3600_000;     // 周五 19:00
  const sat00     = monday00 + 120 * 3600_000;     // 周六 00:00
  const nextMon00 = monday00 + 168 * 3600_000;     // 下周一 00:00

  const t = now.getTime();
  if (t < fri19)     return { state:'S1', progress: (t - monday00) / (115*3600_000), ... };
  if (t < sat00)     return { state:'S2', progress: 1, ... };
  if (t < nextMon00) return { state:'S3', progress: (t - sat00) / (48*3600_000), ... };
  /* t === nextMon00 及以后由下一周的锚点覆盖（tick 会重算，见 3.3） */
}
```

正确性论证（对齐 SRS §3.1）：
- 覆盖全周期：周一 00:00 ≤ t < 下周一 00:00 被三个区间无缝分割，无空洞、无重叠。
- 周日晚场景（验收 A-5 前置）：周日属本周（`daysSinceMonday=6`），落 S3，进度 = 距周六 00:00 / 48h，正确。
- 跨年/跨月：全部基于毫秒差，与日期数值无关，天然正确。

档位（stage）在 `computeState` 内一并计算：

| 状态 | 档位判定 |
| --- | --- |
| S1 | `p<0.15→L0；<0.40→L1；<0.70→L2；<0.95→L3；else→L4` |
| S3 | `p<0.30→F0；<0.70→F1；else→F2` |

### 3.2 时钟调度（clock.js）

- **整秒对齐**：先 `setTimeout` 至下一个整秒边界，再起 `setInterval(1000)`，避免累计漂移（倒计时秒位与真实秒对齐，FR-02-1）。
- **锚点定时器**：每次 tick 时取 `stateResult.anchors.next`，用 `setTimeout(anchors.next - now)` 精确触发一次即时重算（FR-01-2 双保险的前半段；每秒 tick 是后半段）。
- **恢复重算**：监听 `visibilitychange`（`document.visibilityState==='visible'`）与 `window focus`，立即强制 tick（FR-01-3，覆盖 E-3/E-7）。后台标签页 interval 被 CPU 节流到分钟级——不影响正确性，因为恢复时必重算。
- 系统时间被用户改动（E-4）：无检测、以 `Date` 为准，为已知限制，不做防御。

### 3.3 状态切换与转场（controller.js）

状态 diff 逻辑：

```
onTick:
  next = computeState(new Date())
  if next.state !== current.state:  enterState(next, { transition: 'auto' })   // 跨锚点
  else:                             effects.apply(next)                        // 同状态进度推进
```

| 转场 | 触发 | 实现 |
| --- | --- | --- |
| S1 → S2 | 跨周五 19:00 | ① 播放「冰块爆裂」CSS 动画（§4.3，≤2s）② 文案切「解冻成功」停留 ≥1s ③ `media.activateVideo()`（爆裂动画期间并行 `preload`，动画结束即 `play()`，无黑屏间隙） |
| S2 → S3 | 跨周六 00:00 | 无重转场，仅 `effects.apply` 开始叠加 F 档特效（F0 起步本身即平滑入场） |
| S3 → S1 | 跨周一 00:00 | ①「彻底冻住」短动画（≤1.5s，冰层 opacity→1 再整体淡出）② `media.deactivateVideo()`（`pause()` 并置空 `src` 释放内存）③ 图片层按 L0 就位，倒计时文案重置（FR-07） |
| 首次进入 | 页面加载 | 按 `computeState` 直接渲染目标状态，不播跨状态转场（FR-04-2，S2 直接进入可带入场 fade） |

### 3.4 状态机单测（与验收用例直连）

`stateMachine.js` 是纯函数，注入 `Date` 即测，不依赖 DOM/定时器。测试用例 = SRS A-1~A-5 的时间点表（另补边界值：周一 00:00:00.000、周五 18:59:59.999 / 19:00:00.000、周六 00:00 边界、周日 23:59:59.999、进度档位阈值两侧、跨年周）。工具：Vitest。

## 4. 特效技术选型

### 4.1 方案对比（核心决策）

| 方案 | 档内连续性 | 性能 | 体积/复杂度 | WebView 兼容 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **A. CSS 分层 + CSS 变量驱动** | 中（变量插值 + 常驻动画叠加） | 高（transition/animation/opacity/mask 合成友好；filter 每秒一次写入可接受） | 低 | 好（微信/抖音 X5 与 WKWebView 均稳） | ✅ **主体方案** |
| B. Canvas 程序化特效（裂纹生长、粒子融水） | 高 | 中（逐帧重绘，低端 Android 风险） | 高 | 好 | ⛔ 不做主体；保留为 L1 档裂纹的可选增强挂点 |
| C. WebGL shader | 最高 | 高（GPU） | 最高（着色器开发+iOS 低版本/WebView 风险） | 中 | ⛔ 过度设计，否决 |

**选型原则**：进度驱动的「状态量」（冰层覆盖度、色调、清晰度）走 CSS 变量（每秒写一次）；「动感量」（水滴、抖动、发光、冰晶闪烁）走常驻 CSS `@keyframes` 循环（与进度无关，由档位类名开关）。两者叠加同时满足 FR-03-2「档内连续变化」与 FR-09-1「60fps」。

### 4.2 分层结构（DOM）

```
<div class="stage" data-state="S1" data-stage="L2"
     style="--p: 0.52; --pf: 0">          ← effects.js 每秒写入
  <div class="hero">                       ← 主人公图片层
    <img src="hero.png">
  </div>
  <div class="ice-overlay">                ← 冰封覆盖层（解冻时随 --p 消退）
    <div class="ice-tint"></div>           ← 色调层：filter 插值
    <div class="ice-texture"></div>        ← 冰纹纹理层：mask 揭示
    <div class="cracks"></div>             ← 裂纹层（SVG/多个裂片 span，L1+ 显示）
    <div class="drips"></div>              ← 融水滴落动画层（L1+）
  </div>
  <div class="aura"></div>                 ← L4 蓄力发光/抖动层
  <video class="video" muted playsinline loop preload="none" poster="poster.jpg"></video>
  <div class="freeze-overlay">             ← 上冻层（S3 时随 --pf 增强，覆盖于 video 之上）
    <div class="frost"></div>              ← 边缘霜层：mask 内缩 + opacity
    <div class="freeze-veil"></div>        ← 全屏冰层 + backdrop-filter
  </div>
  <div class="hud">…倒计时/进度文案…</div>
</div>
```

S1/S2/S3 三态共用同一个 `.stage` 骨架，仅由 `data-state` / `data-stage` / `--p` / `--pf` 控制——**一套 DOM，状态机换装**，避免重建 DOM 引起的闪烁与内存抖动。

### 4.3 关键特效实现要点

**解冻侧（L0→L4，变量 `--p` = 解冻进度）**：

| 层 | 实现手段 |
| --- | --- |
| 色调（FR-03 L0 偏蓝→L3 恢复） | `.ice-tint { filter: saturate(calc(0.3 + var(--p)*0.7)) brightness(calc(0.75 + var(--p)*0.25)) hue-rotate(calc((1 - var(--p)) * 20deg)); opacity: calc(1 - var(--p)) }`，JS 每秒更新 `--p`，transition 1s 平滑 |
| 冰块消退 | `.ice-texture` 用径向/线性 `mask-image` + `mask-size: calc(200% - var(--p)*120%)` 从中心向外揭示人物；纹理素材为 CC0 冰纹图 |
| 裂纹（L1+） | 预置 5–7 条 SVG 裂纹 path，`stroke-dashoffset` 动画依次「生长」；档位类名控制显隐与条数（L1 显 3 条、L2 显全部），生长本身 `@keyframes` 一次性播放 |
| 融水（L1/L2） | 若干水滴 span，`@keyframes` 循环下落 + opacity 渐隐；`animation-duration` 随档位加快 |
| 蓄力（L4） | `.aura`：`box-shadow`/径向渐变呼吸发光 + hero 层 `transform: translateX(±2px)` 微抖 `@keyframes` |
| 爆裂转场（S1→S2） | 冰纹层按 mask 切成 6–8 块碎片 span，`transform: translate+rotate + opacity: 0` 各自飞散（纯 keyframes，随机 delay 制造层次），总时长 1.8s |

**上冻侧（F0→F2，变量 `--pf` = 上冻进度）**：

| 层 | 实现手段 |
| --- | --- |
| 霜层（F0） | `.frost`：边缘霜花纹理，`mask` 为径向渐变（`mask-size` 随 `--pf` 从 130% 内缩到 60%，即冰从边缘向中心蔓延），`opacity: calc(var(--pf) * 1.6)` |
| 冰封蔓延（F1） | `.freeze-veil { backdrop-filter: blur(calc(var(--pf)*4px)) saturate(calc(1 - var(--pf)*0.6)); background: 冰蓝色渐变; opacity: var(--pf) }` |
| 完全上冻（F2） | 冰纹纹理层 opacity → 接近 1，视频轮廓仅隐约可见（veil 上叠冰纹 + 降亮度） |
| 降级 | `@supports not (backdrop-filter: blur(1px))` 时改用半透明冰色覆盖层模拟（Android X5 老版本兜底，SRS FR-10-2 精神） |

`backdrop-filter` 作用于 video 之上的覆盖层；进度每秒更新一次 + CSS `transition: 1s linear`，视觉上连续（FR-06-1），同时避免逐帧 filter 重绘。

### 4.4 素材策略（对应 SRS §6 / Q-1）

- 开发期占位：主人公用一张 CC0 人物图 + 程序化冰纹（可由 CSS 渐变+噪点 SVG 滤镜生成临时版）；视频用 10s 循环占位 MP4（程序生成或公开样片）。
- 正式素材替换只动 `assets/` 与一个清单常量，DOM/逻辑零改动。
- 冰纹/霜花纹理：优先 CC0（如 ambientCG 冰面纹理），WebP 格式，单张 ≤ 200KB。

## 5. 视频模块设计（media.js）

```
activateVideo():
  video.src = src; video.preload = 'auto';
  const p = video.play();                 // muted+playsinline 满足自动播放策略
  p?.catch(autoplayBlocked)               // E-6：promise 被拒 → 显示「点击开始」遮罩

deactivateVideo():
  video.pause(); video.removeAttribute('src'); video.load();   // 释放解码内存

autoplayBlocked → 「点击开始」遮罩:
  遮罩点击 → video.play() → 成功后展示「取消静音」按钮 → video.muted=false

错误处理（E-5）:
  video 'error' 事件 → 显示 poster 静态兜底 + 重试按钮（重试 = 重建 source 并 play）
  兜底期间状态机/倒计时不受影响（media 层与 effects 层解耦）
```

- 循环播放用原生 `loop` 属性（FR-05-1）；`preload` 在进入 S2 前的 L4 档位提前预热（爆裂转场期间已缓冲，消除切换黑屏）。
- 视频铺满：默认 `object-fit: cover` + 容器 `aspect-ratio` 锁定（FR-05-3，视觉评审后可切 contain）。

## 6. 响应式与布局（FR-08）

- 断点仅一处：`@media (min-width: 768px)`，移动优先编写。
- `.stage` 采用 flex 纵向布局：标题区 / 主视觉区（`flex: 1` + `min-height: 0`）/ HUD 区；主视觉内 hero 与 video 均 `position: absolute; inset: 0` 叠放。
- 特效层全部跟随主视觉容器尺寸（百分比 + `aspect-ratio`），不做 JS resize 计算。
- 横竖屏：竖屏下主视觉取满宽、HUD 收窄为单行倒计时；横屏下主视觉居中限高（`max-height: 72vh`）。
- 微信/抖音 WebView 验证点：`100vh` 抖动 → 用 `100dvh`（带 fallback）；安全区 `env(safe-area-inset-*)` 预留 HUD。

## 10. 风险与决策记录（ADR 摘要）

| # | 决策/风险 | 处置 |
| --- | --- | --- |
| D-1 | filter 每秒写一次仍有重绘成本，低端机档位切换瞬间可能掉帧 | 档位层用 opacity/transform 切换为主，filter 只做色调微调；真机验证 FR-09-1，不达标则把色调层降为纯 opacity 混合 |
| D-2 | 微信 WebView 视频自动播放策略多变 | 必测项；兜底路径（点击开始）已内建，验收 A-6 |
